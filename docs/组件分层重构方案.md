# 组件分层重构方案（已执行第一至三阶段）

## 1. 目的与边界

本方案用于逐步整理本项目的目录、组件边界与组件依赖，使代码按下列方向分层：

```text
app（产品行为、启动编排、UI）
  ↓
services / adapters（采样服务、LVGL 适配、存储服务）
  ↓
device drivers（AHT20、W25Q64、ILI9341、XPT2046、WS2812B）
  ↓
HAL / bus（soft_spi、soft_uart、ESP-IDF driver）
  ↓
ESP-IDF / third_party（lvgl、led_strip、littlefs）
```

本次方案的首要约束是**不改变现有功能和硬件行为**：保留现有引脚、SPI/I2C/GPTimer 使用方式、公开 API、初始化顺序、LVGL 刷新链路和 LittleFS 分区配置。重构期间不升级第三方库，不更换驱动实现，不调整 UI 行为。

本文件保留设计与执行清单，并记录本次实施结果。已完成的迁移未改变 C API、引脚、总线时序、启动顺序或 LittleFS 分区配置。

## 2. 当前问题

### 2.1 同一目录混合了多个抽象层

`components/` 当前同时容纳：

- 软件总线实现：`sim_uart`、`sim_spi`；
- 设备驱动：`aht20`、`W25Q64`、`WS2812B`、`rgb_led`、`LCD`；
- 通用支撑：`platform`、`tools/ringbuffer`；
- 第三方组件：`ESP/led_strip`、`littlefs`、`lvgl`。

其中 `sim_uart` 与 `sim_spi` 是通过 GPIO 和 GPTimer 实现的 UART/SPI 总线驱动，并非应用层通信协议；应归入 HAL / bus。`LCD` 同时实现 ILI9341 显示与 XPT2046/HR2046 触摸，两个独立设备被放在同一个组件中。`littlefs` 同时包含上游核心库、ESP-IDF 挂载封装和测试代码，也存在职责混合。

### 2.2 `app` 组件范围过大

`app/CMakeLists.txt` 将启动入口、LVGL 适配、UI、温湿度/时间/CPU 服务一起编译成单个组件。其结果是：服务不能独立声明依赖和测试；任何 UI 修改都会触及整个应用组件的依赖集合；启动代码直接执行 W25Q64 破坏性通信测试。

### 2.3 板级资源配置分散

GPIO、SPI/I2C 总线、屏幕方向、WS2812B/RGB LED 配置散落在设备驱动的头文件、实现文件与 `app/main.c` 注释中。板子专属信息与芯片驱动逻辑耦合，后续更换接线或复用驱动都会扩大改动范围。

## 3. 目标结构

建议在保持 ESP-IDF 每个实际组件均具备独立 `CMakeLists.txt` 的前提下，逐步迁移到以下结构：

```text
app/
  main.c                              # 入口与启动编排，不实现设备细节
  ui/
    home/
    developer_mode/

components/
  platform/
    platform_log/                     # 统一日志封装
    board_my32/                       # 本板 GPIO、总线、设备配置

  hal/
    soft_spi/                         # 原 components/sim_spi
    soft_uart/                        # 原 components/sim_uart
    common/
      ringbuffer/                     # 原 components/tools/ringbuffer（确认仍需要后迁移）

  drivers/
    sensors/
      aht20/                          # 原 components/aht20
    storage/
      w25q64/                         # 原 components/W25Q64，仅保留驱动 API
    display/
      ili9341/                        # 从 components/LCD 拆出的 lcd.c 与 lcd.h
    input/
      xpt2046/                        # 从 components/LCD 拆出的 touch.c 与 touch.h
    lighting/
      ws2812b/                        # 原 components/WS2812B
      rgb_led/                        # 原 components/rgb_led

  middleware/
    littlefs_vfs/                     # LittleFS 的 ESP-IDF 挂载与 VFS 注册
    diagnostics/
      w25q64_test/                    # 原 w25q64_test.c，测试/诊断功能
      littlefs_test/                  # LittleFS 的 VFS 回归与速度测试

  adapters/
    lvgl_port/                        # 原 app/display/lvgl_adapt

  third_party/
    lvgl/                             # 保留现有第三方源码
    led_strip/                        # 原 components/ESP/led_strip
    littlefs/                         # 仅保留上游 LittleFS 核心源码

docs/
  architecture/
    component_layers.md               # 后续沉淀分层规则与依赖图
```

目录分组是为了表达职责；`hal/soft_spi`、`drivers/storage/w25q64` 等每个叶子目录仍是一个独立 ESP-IDF 组件。

## 5. 依赖规则

### 5.1 允许的依赖方向

```text
app
  -> services / adapters
  -> drivers
  -> hal / platform
  -> ESP-IDF 与 third_party
```

- 上层可以依赖下层；下层禁止依赖上层。
- UI 只能调用服务或适配层公开 API，不能直接操作 GPIO、SPI device handle 或 GPTimer。
- 设备驱动可依赖总线/HAL 抽象和 ESP-IDF 驱动，不可依赖 `app`、UI 或 LVGL 页面。
- `board_my32` 只提供板级配置与资源所有权，不应依赖业务服务或 UI。
- 第三方组件不修改业务代码；必要补丁应单独记录，避免与本地功能代码混放。

### 5.2 重点依赖关系

```text
environment_sensor service
  -> aht20 driver
  -> ESP-IDF I2C driver

w25q64 driver
  -> soft_spi HAL
  -> ESP-IDF GPIO / GPTimer driver

lvgl_port adapter
  -> LVGL third_party
  -> ili9341 driver
  -> xpt2046 driver
  -> board_my32（显示尺寸、方向、共享总线配置）

ws2812b driver
  -> led_strip third_party
  -> ESP-IDF RMT 或 SPI driver
```

`ILI9341` 与 `XPT2046` 共享 SPI2 是硬件事实，不应通过“`touch_init()` 必须先由 `lcd_init()` 调用”的隐式约定表达。迁移后应由 `board_my32` 或独立的显示 SPI 总线组件提供一次初始化、多个 device handle 的能力；但第一期仍保留当前初始化顺序，以避免行为变化。

## 6. 板级组件设计

新增 `board_my32` 的目标是收拢本板专属参数，而不是建立新的硬件驱动层。建议其公开配置结构或只读配置函数，例如：

```c
const board_display_config_t *board_my32_get_display_config(void);
const board_touch_config_t *board_my32_get_touch_config(void);
const board_aht20_config_t *board_my32_get_aht20_config(void);
const board_w25q64_config_t *board_my32_get_w25q64_config(void);
```

首批收拢的配置包括：

- ILI9341：SPI2、MISO=5、SCLK=6、MOSI=7、DC=15、RST=16、CS=17；
- 触摸：独立 CS=8、IRQ=18，以及现有校准数据；
- AHT20：I2C0、SDA=2、SCL=1；
- W25Q64：软件 SPI 的 GPIO36/35/37/38、SPI Mode 0、50 kHz；
- WS2812B：GPIO48、灯珠数、RMT/SPI 后端；
- RGB LED：当前三个 PWM 引脚；
- LittleFS：分区标签 `littlefs` 与挂载路径 `/littlefs`。

在板级配置尚未落地前，不强制修改现有驱动中的宏；这一项应放在后续独立提交中，以便问题能快速定位与回退。

## 7. 分阶段执行计划

### 阶段 0：建立基线（不改功能）

1. 使用项目内 SDK 执行 `./build.sh build`，保存成功构建日志。
2. 在真机上保存启动日志：LittleFS 挂载、W25Q64 通信测试、温湿度服务、LVGL、RGB LED、WS2812B。
3. 记录当前组件依赖、GPIO 占用和 `sdkconfig`。
4. 不修改当前未提交的 W25Q64、LittleFS、分区表相关工作区变更。

验收：构建成功，且启动日志和已有功能与重构前一致。

### 阶段 1：纯目录迁移与 CMake 注册调整

1. 创建 `hal`、`drivers`、`adapters`、`third_party` 等分组目录。
2. 移动独立组件到目标路径；LittleFS 核心、VFS 适配与诊断代码按各自层次拆分。
3. 保留组件名称、源文件名、公开头文件名和 C API 名称。
4. 在根 `CMakeLists.txt` 的 `EXTRA_COMPONENT_DIRS` 显式列出每个嵌套的实际组件目录。
5. 更新 README 中的路径引用，不修改功能代码。

验收：`./build.sh build` 成功；固件功能和启动日志一致；`git diff --check` 无格式错误。

回滚：仅回退本阶段目录移动和 CMake 路径改动即可，不涉及 API 或硬件配置。

### 阶段 2：拆分显示与触摸驱动

1. 从 `LCD` 组件拆出 `ili9341` 与 `xpt2046` 两个组件。
2. 维持原 `lcd.h`、`touch.h` 的函数签名，必要时通过兼容组件转发，避免同时改动 LVGL 适配代码。
3. 明确 `xpt2046` 对共享 SPI 总线的依赖；第一阶段仍由既有显示初始化流程建立总线。
4. 保留触摸校准数据与当前显示方向，不改变坐标变换。

验收：屏幕初始化、LVGL 刷新、触摸点击/滑动、开发者校准页面均正常；无重复初始化 SPI2 的错误。

回滚：恢复为单一 `LCD` 组件；不改变原始 LCD 和触摸源码内容。

### 阶段 3：剥离诊断与服务

1. 将 `w25q64_test.c` 迁入 `middleware/diagnostics/w25q64_test` 或 `app/diagnostics`。
2. 将 `app/main.c` 中直接执行的 W25Q64 自检改为明确的诊断功能开关；默认值保持当前“启动即执行”的行为，直到另行审核更改默认策略。
3. 将 `environment_sensor`、`system_time`、`cpu_usage` 分别形成独立服务组件，使用 `REQUIRES` 精确声明各自依赖。
4. `app/main.c` 只保留启动顺序、错误处理和产品功能装配。

验收：所有服务仍按原频率运行；W25Q64 自检仍使用原地址、原擦除行为和原资源释放顺序；`app` 的依赖列表明显收敛。

### 阶段 4：板级配置收拢与命名清理（单独审核）

1. 引入 `board_my32` 并将硬编码引脚逐项迁入配置。
2. 逐个驱动改为接收配置结构，禁止一次性替换全部驱动。
3. 评审并决定是否将组件名/API 从 `sim_spi`、`sim_uart` 改为 `soft_spi`、`soft_uart`。
4. 保持第三方源码可追溯版本，不在本阶段修改上游 LittleFS 核心。

验收：逐项核对 GPIO、总线、定时器和分区未变；完整构建和真机回归通过。

## 8. CMake 与 ESP-IDF 注意事项

ESP-IDF 自动发现根 `components/` 下的一级组件；采用分组后的嵌套目录时，不能假定它会递归自动发现。每一个实际组件目录都应通过根 `CMakeLists.txt` 的 `EXTRA_COMPONENT_DIRS` 显式注册，例如：

```cmake
set(EXTRA_COMPONENT_DIRS
    "${CMAKE_CURRENT_LIST_DIR}/app"
    "${CMAKE_CURRENT_LIST_DIR}/components/platform/platform_log"
    "${CMAKE_CURRENT_LIST_DIR}/components/platform/board_my32"
    "${CMAKE_CURRENT_LIST_DIR}/components/hal/soft_spi"
    "${CMAKE_CURRENT_LIST_DIR}/components/hal/soft_uart"
    "${CMAKE_CURRENT_LIST_DIR}/components/drivers/sensors/aht20"
    "${CMAKE_CURRENT_LIST_DIR}/components/drivers/storage/w25q64"
    "${CMAKE_CURRENT_LIST_DIR}/components/third_party/led_strip"
)
```

示例只说明机制，实际清单应在阶段 1 根据最终迁移范围完整列出。避免使用不受控的 `file(GLOB ...)` 自动扫描组件，以免新建临时目录或示例工程被意外加入构建。

每个组件的 `REQUIRES` / `PRIV_REQUIRES` 应遵循“谁的公开头文件暴露谁”的原则：

- `w25q64.h` 当前公开 `sim_spi_config_t`，因此 `w25q64` 对 `sim_spi` 必须为 `REQUIRES`；
- `aht20` 不向外暴露 I2C 类型时，对 ESP-IDF `driver` 可使用 `PRIV_REQUIRES`；
- `lvgl_port` 应公开声明 `lvgl`、显示与触摸驱动依赖；
- `app` 仅声明实际直接使用的服务、适配层和产品设备，不应为了间接依赖再列出 `sim_spi` 或 `aht20`。

## 9. 功能保持清单

执行任何阶段前后，必须逐项确认：

- `Hello world!`、芯片信息、最小堆日志仍输出；
- LittleFS 仍从 `littlefs` 分区挂载至 `/littlefs`；
- W25Q64 自检仍能读取 JEDEC ID，并在原测试扇区执行擦写验证；
- AHT20 后台服务仍每 10 秒采样；
- LVGL 保持当前单绘图缓冲、DMA 完成回调和显示方向；
- 触摸仍使用原校准系数，坐标范围仍为 `240x320`；
- RGB LED 流水灯和 WS2812B 点亮行为不变；
- 软件 SPI/UART 的 GPIO、波特率/时序和 GPTimer 使用方式不变；
- LittleFS、W25Q64 和分区表的现有未提交修改不被覆盖。

## 10. 审核决策项

执行前请确认以下事项：

1. 是否接受“阶段 1 只迁目录、保留组件名/API”的低风险策略；
2. 是否接受将 `LCD` 拆为 `ili9341` 与 `xpt2046`，并在第一步保留当前 LCD 先初始化共享 SPI2 的行为；
3. 是否将 W25Q64 自检继续保持为默认启动行为，还是仅在诊断配置开启时运行；
4. 是否确认 `components/tools/ringbuffer` 无业务使用后删除，或保留为通用工具；
5. 是否接受新增 `board_my32` 作为唯一板级引脚与资源配置入口。

在上述决策明确前，只执行阶段 0 或方案文档更新，不开始目录迁移。
